# 高分辨率与混合 DPI

## 当前策略

UI 使用 Slint 逻辑尺寸，窗口与显示器编排使用 winit 物理坐标：

- 主窗和设置窗的控件布局由 Slint 按平台 scale factor 缩放；
- 主胶囊按当前显示器工作区约束四边，设置窗按布局自动计算固定尺寸；
- 休息遮罩的目标矩形使用 `(physical x, physical y, width, height)`；
- 拓扑键包含 `scale_factor.to_bits()`，只改变缩放也会重建遮罩；
- SVG 在构建时由 Slint 处理，不再依赖 Qt Svg/qrc。

Windows 上 winit 在进程初始化时优先启用 Per-Monitor V2 DPI awareness，并为旧系统回退到可用的 per-monitor API；项目不再保留旧 Qt manifest。macOS 使用 AppKit/winit 提供的 backing scale factor。

## 显示器几何来源

首选 winit monitor：位置、物理尺寸和 scale factor 来自同一 handle。

如果 winit 无法列出全部显示器：

- macOS `NSScreen` 的 frame 单位是 point、原点在左下；平台层用主屏 top/left 作为参考，翻转 Y 后乘各屏 backing scale，得到物理像素矩形；
- Windows `EnumDisplayMonitors` 的 `rcMonitor` 在 DPI-aware 进程中作为物理矩形兜底；scale key 暂记 1.0，后续 winit 枚举恢复时会以完整 scale 重新 reconcile。

## 资源取舍

software renderer 的全屏缓冲按物理像素增长。当前 8,416,800 像素单屏的 RGBA 理论缓冲约 32.1 MiB，实测休息态 private footprint 相对主窗增加约 29.75 MiB。多块 4K/5K 屏的内存不能按主窗十几 MiB 估算，详见 [资源测试.md](./资源测试.md)。

## 验收

至少覆盖：

| 布局 | 检查 |
| --- | --- |
| 单屏 100%、150%、200% | 主窗文字清晰，按钮不裁切，遮罩无边缘空隙 |
| 双屏同 DPI | 位置正确，每屏只有一个遮罩 |
| 双屏混合 DPI | 跨屏无放大/缩小突变造成的越界，遮罩按各自物理尺寸铺满 |
| 主屏切换 | 1 秒 reconcile 后布局正确 |
| 热插拔 | 新旧窗口不在剩余屏重叠 |

资源测试 JSON 中的 `overlay_count` 和 `overlay_pixels` 应与测试布局一致；不一致时先排查显示器枚举，而不是比较内存数字。
