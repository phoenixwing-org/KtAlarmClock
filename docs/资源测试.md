# Release 资源测试

本项目的资源验收必须测量独立的、已优化并剥离符号的 Release 应用进程，不能测 Rust test harness、Debug 程序或编译器进程。

## 运行命令

快速功能测试：

```bash
cargo test --workspace
```

Release 资源测试（约 25 秒，不含首次 Release 编译）：

```bash
cargo test --release -p kt-alarm-clock --test resource_usage \
  release_resource_usage -- --ignored --nocapture --test-threads=1
```

测试依次启动两个独立子进程：

1. `idle`：托盘 + 胶囊主窗；
2. `break`：进入休息，并为当前枚举到的每块显示器创建一个遮罩。

每个进程预热 4 秒，再以 250 ms 间隔采样 5 秒，随后由应用自身正常退出。测试模式使用临时配置目录，不读写正式用户配置，也不修改自启动项。

结果会打印到测试输出，并写入 `target/resource-usage.json`。该文件是本机生成物，不提交 Git。

## 指标口径

| 字段 | macOS | Windows |
| --- | --- | --- |
| `max_resident_bytes` | resident size | Working Set |
| `max_private_bytes` | `ri_phys_footprint` | PrivateUsage |
| `average_cpu_percent` | 采样期 CPU time / 墙钟时间 | 同左 |
| `overlay_count` | 实际休息遮罩数 | 同左 |
| `overlay_pixels` | 全部遮罩的物理像素总数 | 同左 |

macOS resident size 包含较多共享系统映射，判断应用自身常驻成本时以 `max_private_bytes` 为主。CPU 百分比按单个逻辑核 100% 的常见口径计算。

资源测试默认只验证：Release 子进程能稳定运行、正常退出且系统指标可读取。不同机器的分辨率、字体缓存和操作系统版本差异较大，因此默认不写死跨机器阈值；CI 可按固定基准机设置以下环境变量启用回归门槛：

- `CLOCK_MAX_BINARY_BYTES`
- `CLOCK_MAX_IDLE_PRIVATE_BYTES`
- `CLOCK_MAX_BREAK_PRIVATE_BYTES`
- `CLOCK_MAX_IDLE_CPU_PERCENT`

## 当前 Rust macOS arm64 基线

采样日期：2026-08-11。Slint 1.17.1、winit、software renderer；测试环境休息时枚举到 1 块显示器，共 8,416,800 个物理像素。

| 模式 | 可执行文件 | Resident | Private / physical footprint | 平均 CPU |
| --- | ---: | ---: | ---: | ---: |
| 主窗空闲 | 9.60 MiB | 80.91 MiB | **17.66 MiB** | **0.0024%** |
| 单屏休息 | 9.60 MiB | 111.28 MiB | **47.41 MiB** | **0.0019%** |

结论：

- 常驻主界面达到“十几 MiB、接近零空闲 CPU”的阶段目标，并且发布文件低于 10 MiB；
- 休息态 CPU 仍接近零，但 software renderer 必须为全屏窗口保留像素缓冲。本机 8.42 百万像素仅 RGBA 缓冲理论值就约 32.1 MiB，实测 private footprint 相对空闲态增加约 29.75 MiB，量级相符；
- 多屏休息内存会随显示器物理像素总数近似增加，不能拿主窗的 17.66 MiB 宣称所有状态都只占十几 MiB；
- 若以后必须压低多块 4K/5K 屏休息态内存，应单独评估“原生纯色背景窗口 + 小尺寸 Slint 交互面板”。这不影响当前无 Qt、无 WebView 结论，但会增加两平台窗口编排复杂度。

早期人工 `vmmap` 曾在遮罩稳定约 150 秒后得到 31.0 MiB、峰值 48.3 MiB。自动测试采用短预热并取采样最大值，因此更保守；后续趋势比较必须使用同一命令、同一显示器布局和同一操作系统版本。

## 与旧 Qt Widgets 的同机对比

旧版取自 Git commit `16c00a4`，使用本机 Qt 5.15.19 arm64 Release 构建。两种实现都在同一块 3600 × 2338、共 8,416,800 物理像素的显示器上测试；每个独立进程预热 4 秒，再以 250 ms 间隔采样 20 次。macOS 指标统一来自 `proc_pid_rusage(RUSAGE_INFO_V4)`，CPU 为采样期 `ri_user_time + ri_system_time` 增量除以墙钟时间。

| 实现 | 发布体积 | 模式 | Resident | Private footprint | 平均 CPU |
| --- | ---: | --- | ---: | ---: | ---: |
| Rust / Slint | **9.60 MiB** | 工作计时主窗 | 80.91 MiB | **17.66 MiB** | 0.0024% |
| Rust / Slint | **9.60 MiB** | 单屏休息 | 111.28 MiB | **47.41 MiB** | 0.0019% |
| Qt Widgets | 24.89 MiB | 工作计时主窗 | 112.27 MiB | **23.13 MiB** | 0.0039% |
| Qt Widgets | 24.89 MiB | 单屏休息 | 220.45 MiB | **125.35 MiB** | 0.0037% |

对比结论：

- Rust 空闲 private footprint 比 Qt 少约 5.47 MiB，降低约 24%；
- Rust 单屏休息比 Qt 少约 77.94 MiB，降低约 62%，约为 Qt 的 38%；
- Qt 遮罩相对空闲增加约 102.22 MiB，Rust 增加约 29.75 MiB，Qt 增量约为 Rust 的 3.44 倍；
- Rust 发布文件比最小自包含 Qt `.app` 少约 15.29 MiB，降低约 61%；
- 两者 CPU 都已接近测量噪声，万分之几的差值不支持“CPU 有显著差异”的结论；
- Qt 遮罩增量符合多个全屏 backing store 与窗口合成缓冲共同存在的量级，但仅凭 footprint 不能断言具体缓冲份数。

### Qt 发布体积为何不能只算业务二进制

旧 Qt 构建 strip 后的裸产物为：

- `KtAlarmClock`：34,752 bytes；
- `libKtAlarmClockUI.dylib`：261,544 bytes；
- 合计 296,296 bytes，约 0.28 MiB。

这个数字不能与 Rust 单文件直接比较，因为裸产物动态依赖 Homebrew 的 QtCore、QtGui、QtWidgets、QtNetwork、QtSvg，并实际加载 `qcocoa`、`qmacstyle`、`qsvgicon`；`qcocoa` 还需要 QtDBus、QtPrintSupport、FreeType 等依赖。

经实际加载验证、确认不再访问 Homebrew 并完成 ad-hoc 签名的最小自包含 `.app`，逻辑文件合计为 26,095,472 bytes，即 **24.89 MiB**。未裁剪的 `macdeployqt` 默认包为 40.20 MiB，但它还带入本程序未使用的 QML、Qt Quick、VirtualKeyboard 与多种图片插件，因此不作为最低必需体积。

### Qt 基线复现

独立 worktree 保留在 `../.worktrees/KtAlarmClock-qt-baseline`，锁定旧提交，不修改当前 `rust` 工作树：

```bash
git worktree add --detach \
  ../.worktrees/KtAlarmClock-qt-baseline 16c00a4

cd ../.worktrees/KtAlarmClock-qt-baseline
cmake --preset macos-release
cmake --build --preset macos-release --parallel

strip -x \
  build/mac/out/bin/KtAlarmClock \
  build/mac/out/bin/libKtAlarmClockUI.dylib
```

旧版没有资源测试模式。为可重复进入休息态，worktree 中保留一个未提交的测试钩子：检测 `KT_QT_RESOURCE_TEST_BREAK` 后通过 `QTimer::singleShot(0, ...)` 分发 `ActionBreak`。它只使业务 dylib 增加 96 bytes，idle 与 break 使用同一份带钩子的二进制；该钩子不进入 `rust` 分支。

```bash
KT_QT_RESOURCE_TEST_BREAK=1 \
  build/mac/out/bin/KtAlarmClock
```

当前对比只覆盖 macOS arm64。最小 `.app` 未包含 Developer ID、公证和 DMG；Windows 仍须在固定基准机按同一口径单独采样。趋势比较以 private footprint 为主，并保持机器、显示器布局、系统版本、预热与采样时长一致。
