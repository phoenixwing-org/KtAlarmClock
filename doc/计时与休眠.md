# 计时与休眠

## 原则

Qt 的 `QTimer` 只负责唤醒刷新，不负责决定真实剩余时间。真实时间差由 QPC/monotonic clock 计算。

这解决三个场景：

- 事件循环卡顿。
- 系统睡眠/唤醒。
- Windows 锁屏/解锁后继续运行。

## 工作阶段

工作倒计时在 `KtClockRuntime` 中运行：

1. `enter_phase(WorkTime)` 调用 `runtime_->start(WorkTime, seconds)`。
2. `KtClockRuntime` 记录 QPC 起点。
3. 1 秒 `QTimer` tick 时调用 `sync_from_monotonic_clock()`。
4. 应用回到 active 时，Controller 也会主动同步一次。
5. 剩余秒数为 0 时发出 `timeout(WorkTime)`。

到期链路：

```text
KtClockRuntime::timeout(WorkTime)
  -> KtAlarmClockController::on_clock_timeout
  -> clock_timeout_impl
  -> enter_phase(WorkBreak)
```

## 锁屏休息阶段

锁屏休息阶段在 `KtLockScreenManager` 中运行：

1. `show(WorkBreak, TimeForce, debugMode)` 启动 `breakClock_`。
2. 如果 `TimeForce > 0`，用 `forceEndMs_ = now + min(TimeForce, WorkBreak)` 记录强制期结束点。
3. 每秒同步休息剩余时间和强制期剩余时间。
4. 应用恢复 active 时重新同步并 `reconcile_screens()`。

休息结束后：

- `breakClock_` 暂停。
- `isForced_ = false`。
- 允许 Resume/Unlock 关闭锁屏。
- 成功退出后发出 `clock_out(WorkBreak)`。

## 锁屏时序风险

锁屏时序的关键是：不能只依赖“进入锁屏那一刻”的状态。

风险点：

- Windows 锁屏/唤醒后事件循环暂停了一段时间。
- 显示器热插拔导致屏幕下标变化。
- QML 窗口可能暂时失焦或被其他全屏窗口覆盖。

当前处理：

- QPC 计算真实剩余时间。
- `ApplicationActive` 时同步计时并重新置顶。
- `screenAdded/screenRemoved` 和 10 秒 watchdog 都会触发 `reconcile_screens()`。
- 关闭事件由 C++ eventFilter 拦截，未满足条件不允许关闭。

## 验收建议

- 工作中睡眠 30 秒以上，恢复后剩余时间应减少相应秒数。
- 锁屏休息中睡眠，恢复后强制期和休息期都应按真实时间推进。
- 休息结束后可以 Resume，未结束且答案错误不能退出。
- 双屏锁屏中拔插副屏，遮罩数量应立即修正。
