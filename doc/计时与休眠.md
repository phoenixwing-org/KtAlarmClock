# 计时与休眠

本文说明在 **合盖、系统休眠、显示器关闭** 等导致 UI 定时器暂停的情况下，各类计时如何保持与真实时间一致。

原则：**凡是有 `phaseStartMs_` 或 `forceEndMs_` 的在跑阶段，唤醒后用系统时钟一次性补算；暂停态无活跃起点，休眠不偷时间。**

---

## 场景一览

| # | 场景 | 休眠前 | 休眠期间 | 唤醒后 |
| --- | --- | --- | --- | --- |
| 1 | **已暂停再休眠** | `phaseStartMs_ = 0`，Timer 停，`counter_` 已冻结 | 墙钟走，但无起点可算，**不计时** | 不调用同步（`!running_`），秒数不变 |
| 2 | **工作中未暂停再休眠** | `phaseStartMs_` 有效，Timer 在跑 | Timer 可能停，墙钟继续 | `ApplicationActive` → `sync_from_wall_clock()` |
| 3 | **锁屏中休眠** | 休息 `breakClock_` 在跑；`forceEndMs_` 有效 | 同上 | `KtLockScreenManager::sync_wall_clocks()` |

锁屏 **没有暂停**：无论是否休眠，休息倒计时与强制期始终按墙钟推进。

---

## 场景 1：暂停后休眠

### 期望

合盖任意时长，唤醒后剩余秒数与暂停时一致。

### 机制

暂停时 `pause()` 已执行：

```
update_remaining_from_wall_clock()  // 最后一次刷新 counter_
phaseStartMs_ = 0                   // 清除起点
phaseDurationSec_ = counter_        // 冻结
running_ = false
```

`update_remaining_from_wall_clock()` 在 `phaseStartMs_ <= 0` 时直接返回，休眠期间即使误触发也不会改 `counter_`。

`KtAlarmClockController` 仅在 **`get_running()`** 时响应 `ApplicationActive`：

```cpp
if (state == Qt::ApplicationActive && mainClock_->get_running())
    mainClock_->sync_from_wall_clock();
```

暂停态不会同步，符合预期。

---

## 场景 2：工作中休眠

### 期望

休眠 5 分钟则剩余时间约少 5 分钟；若休眠期间已到点，唤醒后应进入锁屏。

### 机制

运行中保留：

- `phaseStartMs_` — 阶段开始时刻
- `phaseDurationSec_` — 阶段总秒数

唤醒后：

```
elapsed   = floor((nowMs - phaseStartMs_) / 1000)
counter_  = max(0, phaseDurationSec_ - elapsed)
```

若 `counter_ <= 0`，`sync_from_wall_clock()` → emit `clock_out(WorkTime)` → `clock_timeout_impl` → `clock_start(WorkBreak)`。

### 注意

依赖系统发送 `Qt.ApplicationActive`。若极端情况下未收到，下一次 1s tick 也会校准。

---

## 场景 3：锁屏中休眠

### 期望

- 休息倒计时减少约等于休眠时长
- 强制期（TimeForce）在唤醒后状态正确（可能已结束）
- 多屏锁屏 overlay 在唤醒后仍正常（见 [多屏锁屏遮罩.md](./多屏锁屏遮罩.md)，与计时独立）

### 机制

`KtLockScreenManager` 中：

1. **1 秒定时器**（`tickTimer_`，锁屏可见时运行）
2. **`ApplicationActive`** — 立即 `sync_wall_clocks()` + 多屏 reconcile

`sync_wall_clocks()`：

```
if (breakClock_.get_running())
    breakClock_.sync_from_wall_clock()
sync_force_from_wall_clock()
```

强制期：

```
remaining = ceil((forceEndMs_ - nowMs) / 1000)
```

使用绝对截止时间，休眠任意时长均可一次算对。

### 休息到点但仍在锁屏

若休眠期间休息倒计时已到 0：

- 锁屏内 `breakClock_` 会到期，`running_` 变 false，解锁区可显示（非强制期时）
- 不会自动退出锁屏，需用户解锁
- 主浮窗工作计时在锁屏期间本就暂停，与休息结束无关

## 手动验收步骤

### 1. 暂停 + 休眠

1. 将 `WorkTime` 设为 15 分钟（调试可改短）
2. 开始工作，剩余约 12 分钟时点 **暂停**
3. 合盖或休眠 **2 分钟**
4. 唤醒 → 剩余应仍约 **12 分钟**（误差 ±1 秒）

### 2. 工作中 + 休眠

1. `WorkTime` 设为 **3 分钟**
2. 开始工作，合盖 **2 分钟** 后唤醒
3. 剩余应约 **1 分钟**；再合盖至超过剩余时间，唤醒后应 **进入锁屏**

### 3. 锁屏 + 休眠

1. `WorkBreak` = 10 分钟，`TimeForce` = 2 分钟
2. 进入锁屏，合盖 **5 分钟** 后唤醒
3. 休息倒计时约少 5 分钟；强制期应已结束，可看到解锁按钮/算式

### 4. 暂停按钮（非休眠）

1. 工作中点暂停 → 秒数停住
2. 再点播放 → 从相同剩余继续，**不是**从 WorkTime 重头计

| 步骤 | 状态 | 备注 |
| --- | --- | --- |
| 1. 暂停 + 休眠 | ✅ | 已验证 |
| 2. 工作中 + 休眠 | ⏳ | **需求待理顺**，见下节 |
| 3. 锁屏 + 休眠 | ✅ | 已验证 |
| 4. 暂停按钮 | ✅ | 已验证 |

### 步骤 2：需求待确认

**文档当前写法（墙钟模型）**：

- 工作中合盖/休眠时，**仍计入**工作时长（`phaseStartMs_` 不清零）。
- 唤醒后按 `(now - phaseStartMs_)` 补算剩余；若已到期则 `clock_out` → 进入锁屏。

**与步骤 1 的对比**：

| | 暂停后休眠 | 工作中休眠（现设计） |
| --- | --- | --- |
| 休眠期间 | 不计时 | **计时** |
| 唤醒后 | 剩余不变 | 剩余减少（或进锁屏） |

若产品期望「合盖等同暂停」或「唤醒后必须立刻锁屏/不补算休眠时长」，需先定规则再改实现与本节期望。确认前代码仍按上表「现设计」运行。

---

## 已知限制

| 项 | 说明 |
| --- | --- |
| 进程被杀后重启 | 当前未持久化 `phaseStartMs_` / `forceEndMs_`，计时不会跨进程恢复 |
| 无 OS 原生闹钟 | 极端省电策略下 `ApplicationActive` 可能延迟 |
| 锁屏无暂停 | 设计如此；休息必须按设定时长或解锁流程走完 |
