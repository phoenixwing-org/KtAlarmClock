# 计时与休眠

本文说明在 **系统休眠/挂起** 等导致进程内 1s tick 停转的情况下，各类计时如何保持与真实时间一致。

**合盖不等于暂停**：合盖后若接副屏、系统仍唤醒且本进程每秒 tick 正常，**工作计时继续**；仅当合盖触发睡眠/挂起（tick 停转或 `ApplicationSuspended`）时才冻结工作计时。

原则：**休息时**（锁屏）按墙钟推进；**工作时**系统休眠/挂起则冻结剩余秒数、唤醒续计；**用户手动暂停**无活跃起点，休眠不偷时间；锁屏强制期用 `forceEndMs_` 绝对截止补算。

---

## 场景一览

| # | 场景 | 休眠前 | 休眠期间 | 唤醒后 |
| --- | --- | --- | --- | --- |
| 1 | **已暂停再休眠** | `phaseStartMs_ = 0`，Timer 停，`counter_` 已冻结 | 墙钟走，但无起点可算，**不计时** | 不调用同步（`!running_`），秒数不变 |
| 2 | **工作中未暂停再休眠** | `phaseStartMs_` 有效，Timer 在跑 | **冻结在末次 tick**，休眠不计时 | `Suspended` / tick 间隔检测 → 唤醒后续计 |
| 3 | **锁屏中休眠** | 休息 `breakClock_` 在跑；`forceEndMs_` 有效 | 同上 | `KtLockScreenManager::sync_wall_clocks()` |

锁屏 **没有暂停**：无论是否休眠，休息倒计时与强制期始终按墙钟推进。

---

## 场景 1：暂停后休眠

### 期望

系统休眠任意时长，唤醒后剩余秒数与暂停时一致。

### 机制

暂停时 `pause()` 已执行：

```
update_remaining_from_wall_clock()  // 最后一次刷新 counter_
phaseStartMs_ = 0                   // 清除起点
phaseDurationSec_ = counter_        // 冻结
running_ = false
```

`update_remaining_from_wall_clock()` 在 `phaseStartMs_ <= 0` 时直接返回，休眠期间即使误触发也不会改 `counter_`。

`KtAlarmClockController` 监听 `applicationStateChanged`：暂停态收到 `ApplicationActive` 时 `resume_after_system_sleep()` 直接返回，不会误续计；`sync_from_wall_clock()` 仅在运行中由 tick 驱动。

## 场景 2：工作中休眠

### 期望

**工作时**系统休眠/挂起期间**不计时**（自动冻结，非用户点暂停）；唤醒后从冻结的剩余秒数**继续**工作倒计时。若冻结时剩余已为 0，唤醒后进入锁屏。

**休息时**（锁屏 `WorkBreak`）逻辑不变，仍按墙钟推进。

### 机制

1. **`Qt::ApplicationSuspended`**（Qt 5.15+，部分平台）→ `enter_system_sleep()` 立即冻结 `counter_`。
2. **tick 间隔检测**（兜底）：两次 tick 间隔 `> 12s` 时，按**末次 tick 时刻** `freeze_for_system_sleep_at(lastTickMs_)`（阈值故意偏大，避免 UI 卡顿误判；未接副屏的合盖睡眠、系统睡眠常用此路径；**副屏仍在用时 tick 通常不停，不会误冻**）。
3. **唤醒续计**（多路径，Windows 上 `ApplicationActive` 常不可靠）：
   - `Qt::ApplicationActive`
   - **`WM_POWERBROADCAST` 恢复**（`KtWindowsWakeNotifier`）
   - **唤醒看门狗**：休眠冻结后进程定时器恢复跑、且距末次 tick ≥ 12s → `try_resume_after_wake()`
4. **墙钟纠偏**：若 `phaseStartMs_` 落在系统时间之后（唤醒/NTP 回拨），`realign_phase_start_if_ahead()` 对齐起点，避免显示长时间不走秒。
5. 若已到期则 `clock_out(WorkTime)`。

与**用户手动暂停**的区别：手动暂停唤醒后不会自动续计；休眠冻结会在回到前台时自动续计（多路径，见上）。

**播放/暂停与休眠冻结**：仅当 `get_running()` 为真时执行暂停；休眠冻结后点「继续」走 `clock_start(WorkTime)` 续计，避免误触暂停。

### 合盖、副屏、锁屏与休眠

本应用**不监听合盖硬件事件**，只根据 **进程是否仍在跑 tick** 与 **`ApplicationSuspended`** 判断是否挂起。

| 情况 | 工作计时 |
| --- | --- |
| 合盖但接副屏、系统仍唤醒、tick 正常 | **继续计时** |
| 合盖触发睡眠 / 系统睡眠 / 挂起（tick 停或 `Suspended`） | 冻结，唤醒续计 |
| 仅 Win+L 锁屏且 tick 仍每秒触发 | 仍计时 |
| 锁屏且 tick 停转 | 间隔检测会冻结 |

因此：**合盖 ≠ 暂停**；是否冻结取决于系统是否真正挂起、本进程 tick 是否停转，而不是盖子状态本身。

## 场景 3：锁屏中休眠

### 期望

- 休息倒计时减少约等于休眠时长
- 强制期（TimeForce）在唤醒后状态正确（可能已结束）
- 多屏锁屏 overlay 在唤醒后仍正常（见 [多屏锁屏遮罩.md](./多屏锁屏遮罩.md)，与计时独立）

### 机制

`KtLockScreenManager` 中：

1. **1 秒定时器**（`tickTimer_`，锁屏可见时运行）
2. **`ApplicationActive`** — 立即 `sync_wall_clocks()` + 多屏 reconcile

`sync_wall_clocks()`：

```
if (breakClock_.get_running())
    breakClock_.sync_from_wall_clock()
sync_force_from_wall_clock()
```

强制期：

```
remaining = ceil((forceEndMs_ - nowMs) / 1000)
```

使用绝对截止时间，休眠任意时长均可一次算对。

### 休息到点但仍在锁屏

若休眠期间休息倒计时已到 0：

- 锁屏内 `breakClock_` 会到期，`running_` 变 false，解锁区可显示（非强制期时）
- 不会自动退出锁屏，需用户解锁
- 主浮窗工作计时在锁屏期间本就暂停，与休息结束无关

## 手动验收步骤

### 1. 暂停 + 休眠

1. 将 `WorkTime` 设为 15 分钟（调试可改短）
2. 开始工作，剩余约 12 分钟时点 **暂停**
3. 触发系统睡眠/休眠 **2 分钟**（合盖且未接副屏，或开始菜单睡眠）
4. 唤醒 → 剩余应仍约 **12 分钟**（误差 ±1 秒）

### 2. 工作中 + 休眠

1. `WorkTime` 设为 **3 分钟**
2. 开始工作，触发系统睡眠 **2 分钟** 后唤醒
3. 剩余应仍约 **3 分钟**（睡眠期间不计时），并自动继续倒计时
4. 再睡眠直至剩余耗尽后唤醒，应 **进入锁屏**

**副屏对照**（可选）：接外接屏、电源选项「合盖不操作」，合盖后继续在外屏工作数分钟 → 工作倒计时应**正常减少**（未冻结）。

### 3. 锁屏 + 休眠

1. `WorkBreak` = 10 分钟，`TimeForce` = 2 分钟
2. 进入锁屏，系统睡眠 **5 分钟** 后唤醒
3. 休息倒计时约少 5 分钟；强制期应已结束，可看到解锁按钮/算式

### 4. 暂停按钮（非休眠）

1. 工作中点暂停 → 秒数停住
2. 再点播放 → 从相同剩余继续，**不是**从 WorkTime 重头计；**应立即**看到数字减 1（首秒反馈）

### 5. 唤醒后不走秒（回归）

1. 工作中合盖/睡眠数分钟后开盖
2. 应自动续计；若曾卡住，拨系统时间不应再成为唯一恢复手段
3. 数字不应反常增大（如 45 分变 121 分）

## 已知限制

| 项 | 说明 |
| --- | --- |
| 进程被杀后重启 | 当前未持久化 `phaseStartMs_` / `forceEndMs_`，计时不会跨进程恢复 |
| 无 OS 原生闹钟 | 极端省电策略下 `ApplicationActive` 可能延迟 |
| 锁屏无暂停 | 设计如此；休息必须按设定时长或解锁流程走完 |
| 墙钟回拨 | 已钳制 `elapsed≥0`，避免剩余反常增大；若 `phaseStartMs_` 落在未来则 `realign_phase_start_if_ahead()` |
| 启动首秒反馈 | 仅播放/继续：`leanFirstSecond` + 立即 `on_tick()`；Next、±60s 不抢 1 秒 |
